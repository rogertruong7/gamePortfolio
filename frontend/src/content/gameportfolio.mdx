## What it is

You're probably reading this inside it. The site is a small 3D town where you steer a character to a building, stand in the doorway and go in to reach About Me, Projects, Experiences or Skills. Each project and job also has its own URL, so a page can be shared without the game.

## Moving around

You can move in two ways, and both run every frame inside `useFrame`:

- **Keyboard.** WASD or the arrow keys move relative to where the camera is facing, so "up" always means away from you.
- **Click to move.** Clicking the floor casts a ray against the floor mesh to set a target, and the character walks there. A marker shows the spot.

The floor has to tell a click from a camera drag, since both start with the mouse button going down. A press shorter than 150 milliseconds counts as a click.

Speed is multiplied by the frame's delta so the character moves at the same pace at any frame rate, and the character turns smoothly towards its direction of travel rather than snapping.

## Collision

Walking through walls would ruin the illusion, but the buildings are detailed models, so I don't test against their geometry. `Static.jsx` holds a list of invisible `Box3` walls, and the character is treated as a sphere with a radius of 5.

Stopping dead on contact feels bad, so the character slides instead:

1. Find the closest point on the wall and work out the collision normal from it.
2. Project the movement direction onto the plane of that normal, which removes the part going into the wall.
3. Check the slide for a collision too, then apply it if it's clear.

The pond needed more than axis-aligned boxes, so its edge has its own rotated hitboxes.

## The camera

The camera sits at a fixed offset from the player and follows with a lerp. Dragging the mouse orbits it by rotating that offset with a quaternion. Vertical rotation is clamped so it can't flip, and it keeps a minimum height so it stays above the ground.

## Doors

Trigger zones are another list of `Box3` values in `Static.jsx`. Each frame, `Doorway.jsx` checks whether the character is inside one and shows an enter prompt if so. Where two zones overlap, the prompt offers both.

When you go in, the canvas is hidden with `display: none` rather than unmounted, so the models don't reload when you come back. A black panel sliding off the screen covers the switch.

## Keeping it fast

The game loop runs every frame, so small costs add up. A later performance pass made these changes:

- `Doorway` was calling seven state setters every frame. It now remembers the last zone and returns early if nothing changed.
- Collision checks reuse a shared `Sphere` and `Vector3` instead of allocating new ones each time.
- Camera rotation moved from React state to refs, so moving the mouse no longer causes a re-render.
- `Buildings`, `Details` and `Text` are memoised, and text geometry is memoised too.
- Shadows moved from `PCFSoftShadowMap` to the cheaper `PCFShadowMap`.

## The rest of the site

Inside the buildings, pages use a typewriter dialog box in the style of an RPG, with a menu you can drive with the arrow keys. Models are compressed GLB files, and a loading screen shows progress until the buildings are ready. First-time visitors get a tutorial that holds back keyboard controls until it's dismissed. There's also background music and sound effects with a mute button.
