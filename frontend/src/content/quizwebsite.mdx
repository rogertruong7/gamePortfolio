## What it is

An Express API in TypeScript for a game-style live quiz, where an admin runs a session and players answer from their own devices. This repository is the backend only. The routes are documented with Swagger UI at `/docs`, with versioned paths under `/v1` and `/v2`.

## What it covers

| Area | Routes |
| --- | --- |
| Accounts | Register, log in, log out, update details, change password |
| Quizzes | Create, list, read, rename, change description or thumbnail, transfer to another user |
| Trash | View, restore, empty |
| Questions | Create, update, delete, move, duplicate |
| Sessions | Start a session, list active and inactive sessions, read status |
| Players | Join with a name, read status, read a question, submit an answer, see results |

## How it works

### Accounts

Sessions are UUID tokens passed in a header, and logging out removes the token. Passwords are stored as SHA-256 hashes, with past hashes kept so a password can't be reused. The user record also counts successful logins and failed attempts.

Each operation validates its input and throws a specific HTTP error: a bad token is a 401, a quiz owned by someone else is a 403, and invalid input is a 400.

### Quizzes and trash

Deleting a quiz moves it to a separate trash store rather than removing it, so it can be restored until the trash is emptied. Each question has a duration, points, a thumbnail and a list of answers.

### Sessions and players

A session takes a copy of the quiz as it stands, so later edits don't affect a game in progress. It starts in the `LOBBY` state, with a limit of 50 for auto-start and at most 10 active sessions per quiz. Players can only join during the lobby, and a player who doesn't give a name gets a random one.

Answer submission records when each player submitted. Results then give the players who got a question right, ordered by how fast they were, along with the average answer time and the percentage correct.

The route that moves a session between states isn't in this repository, so this code doesn't run a full game on its own.

## Persistence

There's no database. The data store is JSON files on disk, one each for quiz data, session tokens and trash, read and written through helpers in `dataStore.ts`. That's easy to inspect and reset, and it doesn't handle much data or concurrent writes.

## Tests

The repository has 186 Jest tests that make HTTP requests to a running server, covering auth, quizzes, trash and sessions, including the error cases for each route.
