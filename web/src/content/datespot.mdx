## What it is

Datespot is a Spring Boot REST API for an app where people review date spots. It's backend only. The repository has an Angular folder, but it's still the default scaffold.

## What works

| Area | Endpoints |
| --- | --- |
| Auth | Register, authenticate, refresh token, log out |
| Users | Change password, edit profile, list a user's posts |
| Social | Follow, unfollow, list followers and following |
| Reviews | Paginated list, read, create, partial update, delete |

Each area is its own package with a controller, service and repository. Swagger UI is generated from OpenAPI annotations.

## Authentication

Sessions are stateless and requests carry a JWT, checked by a filter that runs before Spring's username and password filter.

A plain JWT stays valid until it expires, so you can't really log someone out. To get that control back, I store issued tokens in a `Token` table:

1. Logging in or refreshing revokes all of the user's existing tokens, then saves the new one.
2. Logging out marks the stored token as expired and revoked.
3. The filter is meant to reject anything marked that way.

Step 3 is written but currently commented out, so today the filter only checks the signature, the expiry and that the user exists. Turning it on is the next change I'd make.

Access is controlled by `USER`, `MANAGER` and `ADMIN` roles, each with a set of fine-grained permissions such as `ADMIN_DELETE`.

## Reviews and following

A review has a title, text, location and rating. Updates apply only the fields you send, and changing a review you didn't write returns a 403.

Followers are a many-to-many relationship from `User` to itself through a `user_following` join table. A review's visibility comes from its author: new reviews inherit the user's public setting, and a repository query can update all of a user's reviews when that setting changes.

## What isn't finished

The itinerary and location packages have controllers and repositories, but their entities still carry placeholder fields (author and ISBN), so they don't model real places yet. A review's location is a plain text field for now.
