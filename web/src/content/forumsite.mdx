## What it is

A Q&A forum built without a framework: one `index.html`, about 1,300 lines of JavaScript in `main.js` and plain CSS. My work is the frontend, which talks to the Express and JSON file API in the repository's `backend` folder. It isn't deployed, so you'd run it locally to try it.

## What you can do

- **Accounts.** Register, log in and log out, with the session kept across refreshes.
- **Threads.** Create, edit, delete, like and watch. The sidebar shows five at a time with a "view more" button.
- **Comments.** Reply to a thread or to another comment, like, edit, and see how long ago each was posted.
- **Profiles.** See a user's threads and watched threads, and update your own email, password, name and picture.
- **Admin.** Admins can edit or delete anything, and can change other users' permission level.

## How it works

### One page, many screens

All the screens are already in the HTML as sections with a `.screen` class. Switching means removing `active` from all of them and adding it to the new one. The current screen is saved in `localStorage`, so a refresh brings you back to it rather than to the login page.

### Keeping fetches together

The API returns thread IDs, then details one at a time, and author names come from a separate call. So listing threads is a chain: get the IDs, `Promise.all` the details, then `Promise.all` the users. To decide whether to show "view more", the code asks for the next page and hides the button if it comes back empty.

### Nested comments

Each comment can have a `parentCommentId`. When rendering a reply, the code finds the parent's element and places the reply under it, building the tree directly in the DOM.

### Permissions that can change

A user can be promoted or demoted while using the site, so a poll runs every 60 seconds to refresh the admin flag. Edit and delete controls appear if you own the item or you're an admin.

### Images and layout

Profile pictures go through `FileReader` and are sent to the API as data URLs. The responsive layout lives in a dedicated `mobile.css` with its own breakpoints.
